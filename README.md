# tnt-trace-otlp

Выгрузка трасс [`tnt-trace`](https://github.com/tnt-skein/tnt-trace)
в коллектор OpenTelemetry по OTLP/HTTP в JSON, сжатом gzip: фоновый
файбер забирает партии закрытых отрезков из очереди трассы, шлёт их
коллектору и разбирает его ответы по правилам OTLP.

```lua
local trace = require('tnt.trace')
local otlp = require('tnt.trace.otlp')

trace.configure({ sample_rate = 1 })             -- настройки трассы — до старта выгрузки
otlp.start({ endpoint = 'http://otel-collector:4318', service_name = 'panel' })   --> true

trace.within('report.build', function() end)     -- записанный отрезок ждёт в очереди
otlp.flush()     --> { { spans = 1, ok = true, status = 200, rejected = 0 } }
otlp.stop()      -- цикл встал, запись отрезков выключена
```

`start` сам собирает клиент к коллектору, ставит крюки трассы — клиентских
отрезков `tnt-http` и отрезков `producer` и `consumer` загруженным очередям
`tnt-queue`, `tnt-event`, `tnt-amqp`, `tnt-kafka` — и включает запись
в `tnt-trace`: приложение получает трассы в Tempo, Jaeger или Grafana без
единой своей строки сверх `otlp.start`.

## Зачем

- **Трасса только складывает.** `tnt-trace` кладёт закрытые отрезки
  в очередь с потолком, а вывезти их с узла — отдельная работа с клиентом
  HTTP, циклом и повторами. Трассу берут все, кому нужен лишь `trace_id`
  в журнале, поэтому выгрузчик — отдельным пакетом.
- **Коллектор строг.** Опознаватели — шестнадцатеричной строкой, время —
  десятичной строкой наносекунд, род и статус — целыми: ошибка в любом
  из трёх стоит всей партии. Ответы разбираются по OTLP: 429, 502, 503,
  504 и сеть — повтор той же партии с отступом по степени двойки и не
  раньше `Retry-After`, прочие отказы — партия выбрасывается и считается.
- **Узел не ждёт.** Отрезок кладётся в очередь без уступки управления,
  партия уходит из фонового файбера раз в секунду, а набравшаяся полная
  партия будит цикл, не дожидаясь такта.
- **Тайны не уезжают.** Атрибут с именем тайны уходит скрытым, строки
  проходят правило тайн журнала `tnt-log`.

## Установка

```sh
tt rocks install tnt-trace-otlp --server=https://tnt-skein.github.io/rocks
```

Или из исходников:

```sh
git clone https://github.com/tnt-skein/tnt-trace-otlp.git
cd tnt-trace-otlp && tt rocks make
```

Зависит от `tnt-trace`, `tnt-http`, `tnt-retry`, `tnt-loop`,
`tnt-compress`, `tnt-log`, `tnt-clock`, `tnt-must` и `tnt-external` —
все ставятся с того же сервера роков.

## Как пользоваться

| Вызов | Что делает |
|---|---|
| `start(opts)` | клиент к коллектору, крюк клиентских отрезков, запись, будильник очереди, цикл; `true` либо `nil, err`; повторный вызов перенастраивает |
| `stop()` | останавливает цикл и выключает запись; накопленное не шлёт |
| `flush()` | отправляет накопленное сейчас, отдаёт исход каждой партии |
| `status()` | цикл, запись, настройки, счётчики отрезков и партий, ждущая партия |

Настройки `start`: `endpoint` (к нему дописывается `/v1/traces`,
умолчание `http://127.0.0.1:4318`), `service_name` (обязательна),
`resource`, `headers`, `client` (прочие настройки `tnt-http`), `batch`
(512), `interval` (1 с), `timeout` (5 с), `retries` (5), `compression`
(`gzip` либо `none`).

Негодная форма настроек — исключение на строке вызывающего; клиент,
который не собрался, и очередь, которую уже снимает Sentry, — отказ
парой, и идущая выгрузка остаётся как была:

```lua
otlp.start({ service_name = 'panel', headers = { ['Content-Encoding'] = 'identity' } })
--> nil, клиент к коллектору не собран: заголовок Content-Encoding задаёт выгрузчик: сжатие — настройкой compression
```

## Проверки

```sh
make deps          # luatest, luacheck, luacov с cluacov и зависимости пакета в .rocks
make check         # форматирование, линт, проверки, покрытие с порогом 100 %
make mutants-all   # мутационное тестирование утилитой tnt-mutants из PATH, порог 100 % убитых
make otel-up       # коллектор OpenTelemetry в докере для живых проверок; make otel-down — погасить
```

108 проверок, из них 8 живых. Покрытие строк — 100 %, убитых мутантов —
100 % (290 мутантов в четырёх модулях). Выгрузчик проверяется
на настоящих трассе, клиенте и цикле с двойником libcurl, сжатие —
настоящей zlib байт в байт; живые проверки идут против коллектора
`grafana/otel-lgtm` с поиском отправленного отрезка в Tempo, а без
поднятого коллектора пропускаются.
